# 许可、归属与贡献授权(Licensing & Attribution)

## 背景

本仓库是上游 `AI-Novel-Writing-Assistant` 的独立衍生版本,由当前维护者独立演进。上游代码按 AGPL-3.0-only 分发,本仓库继续沿用同一许可;同时接受外部贡献,需要一个明确的贡献授权路径,避免再分发时出现权利缺口。

## 决策

1. **单一开源许可**:本项目按 AGPL-3.0-only 分发。服务型商用并不被禁止,但必须完整遵守 AGPL,包括向网络用户提供对应源码。不得在许可证之外附加“服务型商用须单独授权”等限制。
2. **保留上游归属**:`NOTICE` 明确本仓库为独立衍生版本,上游版权与许可条款保留;本仓库的修改与新贡献归当前维护者与贡献者。
3. **CLA 采用“贡献者保留版权 + 授予维护者再许可权”**:不要求版权转让,但允许维护者将贡献按 AGPL-3.0-only 或项目后续采用的开源许可证分发。CLA 不再承诺商业再许可。
4. **不以逐文件版权头作为唯一事实源**:`LICENSE`、`NOTICE`、`CLA.md`、`CONTRIBUTING.md` 与各 `package.json` 的 `license` 字段是权威来源;新增文件无需写版权头。
5. **不内置无许可归属的第三方素材**:引入第三方代码、提示词、数据、模型输出或素材前,必须确认许可兼容性并在 `NOTICE`、PR 或相关目录中保留来源与许可证。

## 当前规则

1. **许可文件职责**
   - `LICENSE`:AGPL-3.0 完整原文,不添加衍生说明或商业限制;
   - `NOTICE`:上游归属、独立衍生声明、上游历史许可与当前许可说明、商业合作说明;
   - `CLA.md`:贡献者权利确认、版权保留、按 AGPL 分发的授权范围;
   - `CONTRIBUTING.md`:提交即视为同意 CLA 的流程说明与第三方素材披露要求;
   - `README.md`「License」段:用户视角摘要并链接以上文件。
2. **包声明一致**:根与各 workspace 包(`client`/`server`/`shared`/`desktop`/`site`)的 `license` 必须统一为 `AGPL-3.0-only`;新增包必须同步声明。
3. **第三方素材**:贡献或引入第三方代码、提示词、数据、模型输出时,必须在 PR/提交说明中写明来源与许可证;不得引入与 AGPL 不兼容的素材。若第三方素材自带独立许可(例如 Apache-2.0 的 Agent Skill),必须保留其许可证与归属,或直接移除。
4. **不新增冲突许可文件**:子目录不得放置与根 `LICENSE` 冲突的许可声明;确需例外时先更新本 wiki 并说明理由。
5. **商业合作边界**:可以对外提供“商业合作联系方式”,但不得宣称 AGPL 之外还需要商业授权,也不得替上游权利人发放商业授权。上游代码的商业授权只能由上游权利人提供。

## 失败模式

- **新增包未声明 license**:分发时许可范围不清;按第 2 条补齐并加守卫(如需要)。
- **贡献未走 CLA**:贡献者未明确授权,后续再分发可能出现权利缺口;PR 模板/贡献指南必须保留 CLA 链接。
- **上游归属被移除**:违反 AGPL 的版权保留要求;`NOTICE` 的上游声明不得删除。
- **复制第三方素材未标注**:产生许可污染;在引入前确认许可证并在 PR 中披露;能删除的复制应优先删除。
- **在 LICENSE 中附加商业限制**:违反 AGPL §10,且维护者无权替上游发放商业授权;合作说明只放在 `NOTICE`/`README`,不得改变 AGPL 权利。
- **品牌更名后归属混乱**:更名(OPS-2)只影响产品名,不改变 `NOTICE` 中的衍生与版权事实;不得借更名抹除上游归属。
